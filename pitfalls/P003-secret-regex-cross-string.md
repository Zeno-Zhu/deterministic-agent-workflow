# P003 · 密钥正则跨字符串边界，把一行 `console.log` 的展示文本判成硬编码密钥

> 冷存件：**默认不读**。只有当 `INDEX.md` 中本行匹配到当前现象时才打开。

## 现象

新增 4.14「硬编码密钥」检查后，对 32 个已装 skill 全量跑一遍，唯一一条命中是：

```text
ERROR: 疑似硬编码密钥/令牌（值不回显）：
  feishu-suite/scripts/extract.mjs:63（键值赋值）
```

人工看那一行，是**打印展示**用的，不是密钥：

```js
console.log("token    :", DATA.meta?.token ?? "(未知)");
```

## 根因

第一版正则是：

```text
\b(api[_-]?key|apikey|secret|token|password|…)\b \s*[:=]\s* ["'] ([^"'\n]{12,}) ["']
```

两处没有约束，于是它**跨过了字符串字面量的边界**：

1. 键前面**可以是任何东西**，包括一个引号 —— `"token` 就这样被当成键；
2. 键后面 `: "` 里的那个引号是**展示字符串的结束引号**，正则却把它当成了值的前引号；
3. 值只排除了引号和换行，**没排除空白** —— 于是 `, DATA.meta?.token ?? ` 这种带空格的表达式被当成了值。

**看起来是「检查太严」，其实是「宽正则左右两侧都没有形态约束」。**

## 解决方案

两侧同时加约束（`scripts/wfsb_check/constants.py`）：

```text
(?i)(?:^|[\s,;{([])['\"]?          # 键必须落在代码边界上，不能在引号中间
(api[_-]?key|apikey|secret|token|…)
['\"]?\s*[:=]\s*['\"]
([A-Za-z0-9_\-][A-Za-z0-9_\-._+/=:@]{15,})   # 值必须「像密钥」：无空白、无逗号括号、字母数字开头
['\"]
```

改完复测：`feishu-suite` 不再命中；反面样本里的真密钥（运行时拼出的 `sk-` 串）**仍然命中**。

## 为什么不是别的方案

- ❌ 加目录/文件白名单放过 `extract.mjs` —— 等于让检查在**最该看的地方**失明；
- ❌ 只改成 `\b`（词边界）—— `"token` 里 `token` 本身就有词边界，拦不住；
- ❌ 把「值里不能有空格」当成唯一补丁 —— 治了这一个样例，下一个样例（值里没空格但跨串）照样过。

## 复现条件

- 环境：跨机通用
- 触发：正则匹配「键: 值」这类成对结构，且两侧只约束形状、不约束边界
- 概率：必现（只要有打印/日志/展示文本里出现同名词）

## 通用性判定

- 判断：`✅ 一类操作`
- 「换个项目还成立吗」自检：成立 ——
  **凡是「宽正则 + 成对结构」的检查，都必须同时约束左边界和右侧取值形态，否则一定会跨语义边界误报。**
  反过来，这也是「检查一旦喊狼来了就会被无视」的通用代价。
