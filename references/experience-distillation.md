# 经验的萃取与归属 VNext

> 本文件是「**一条经验该写进哪一层、写成什么样**」的**唯一权威**。
> 与 `multi-platform-routing.md` 的分工：那边管**流程**（主线 vs 差异层），
> 这边管**经验**（同一把尺子，但对象是"坑 / 判据 / 教训"）。
> 契约模板见 `vnext-contracts.md` §12。

## 0. 问题：经验不萃取，就会**串味**或**沉底**

| 病症 | 长什么样 | 后果 |
|---|---|---|
| **串味** | 把 A 渠道的经验写进主线或别的渠道 | B 渠道照着做 → 报错，且**报错形态和根因无关**，查不出来 |
| **沉底** | 跨渠道通用的经验被写进了某一条渠道差异层 | 其余 5 条渠道**永远学不到**，各自再踩一遍 |
| **发胖** | 不分层，全塞进 `SKILL.md` | 每次触发都读全部内容，关键红线被淹 |
| **僵化** | 单项目 / 单次的经验直接写成永久规则 | 换个项目就失效，却还在被执行 |

★ 四种病**根因是同一个**：**没有先问"这条经验适用于多大范围"就落笔。**

---

## 1. 核心动作：**三问萃取**

任何一条经验，落笔前**必须**按顺序问完三句：

```text
这条经验……
│
├─ ① 换个渠道还成立吗？ ── 否 ──→ 【渠道特性经验】→ 该渠道差异层 · Own Pitfalls
│    （云鲸恒 30s、不能传音频）      ⛔ 不许进主线，也不许进别的渠道
│
└─ 是
    │
    ├─ ② 换个项目还成立吗？ ── 否 ──→ 【项目局部事实】→ 项目侧 docs/
    │    （某剧第 7 集偏大）           ⛔ 不许进任何 skill
    │
    └─ 是
        │
        ├─ ③ 换个域还成立吗？ ── 否 ──→ 【域级通用经验】→ 主线 SKILL.md 域级坑节
        │    （成片太短 = 台词太少）      这是主线最该攒的东西
        │
        └─ 是 ──────────────────────→ 【方法论 / 跨域】→ workflow-skill-builder
                                         （引用关系必须可对账 —— 见本文件 §5）
```

★ **最常问错的是 ①**：很多"看起来是流程问题"的坑，其实是渠道取值问题；
反过来也一样。**判据是"换个渠道还成立吗"，不是"它像不像流程"。**

> 记忆口诀：**「换渠道 → 换项目 → 换域」，三问定层。**

## 2. 四层归属表（含第五类：环境事实）

| 层 | 适用范围 | 落到哪 | 写法要求 | 典型例子 |
|---|---|---|---|---|
| **渠道特性** | 只对本渠道成立 | 该渠道差异层 skill 的 `Own Pitfalls` 节 | 一句话结论 + **触发条件** + 处置；标 `replace`/`append`/`forbid` | 「本渠道不能传参考音频」；「模型名错时上游伪装成限流」 |
| **域级通用** | 跨渠道成立，但只在这个域 | 主线 `SKILL.md` 的**域级坑**节 | 一句话结论 + 一句为什么；**可机械判定**的给判据 | 「成片太短 = 台词太少，不是档位问题」；「组号必须纯数字」 |
| **项目局部** | 只对某部剧 / 某次任务成立 | 项目侧 `docs/` 或任务目录 | 写清**是哪部剧 / 哪个日期**；不进 skill | 「肥皂8 第 7 集 19 组偏大」 |
| **方法论** | 跨域成立 | `workflow-skill-builder` | 抽象成**判据 / 流程**，不带具体平台与项目名词 | 「引用关系必须可对账，否则静默失效」；「参数只能整档给」 |
| ★ **环境事实** | 不随渠道、不随项目变，**但也不是流程** | 环境红线表（项目 `MEMORY.md`）+ `docs/经验与避坑.md` | 写清**现象 → 根因 → 对策**三段；给**可直接跑的判据** | 外层必须用系统 Python 3.14；`python -c` 反斜杠被改写；宿主守卫拦批量删 |

> ★ **「环境事实」是独立的一类，别硬塞进上面四层。**
> 它既不是"流程"（不改流程），也不是"渠道取值"（不该进差异层）。
> 硬塞的结果通常是：进主线污染流程、进差异层让其余渠道跟着串味。

## 3. 写法的三条纪律

### 3.1 每条经验必须给出**可判定的触发条件**

❌ 「注意时长别错」——不知道什么时候该注意
✅ 「**当剧本已带时长标注时**，跳过加时长步骤」——条件可见，能机械判定

> 判据：**读完能回答"我什么时候该想起这条"**。答不上来 = 写了个寂寞。

### 3.2 结论要能**独立读懂**，不许依赖上下文

❌ 「按上面说的方法处理」
✅ 「限流期反复失败 → 继续重试到 4~6 次；**别改提示词 / 资产 / 组**」

理由：经验被读到时，**往往是跨会话、跨项目的**。依赖上下文的写法，
在它真正需要被用上的场合**恰好不可用**。

### 3.3 必须标**出处强度**（防止单次经验被当成定律）

| 强度 | 标记 | 处理 |
|---|---|---|
| 实测复现 ≥3 次 | `实测` | 可写成规则 |
| 实测 1~2 次 | `初步` | **先备案**（冷存 `pitfalls/INDEX.md`），暂不写成永久规则 |
| 推断 / 未验证 | `待证` | 显式标 `待证`，**禁止**写成命令式规则 |

> 与 `file-governance.md` §3 的「备案 → 命中计数 → ≥3 次晋升」是同一套。

## 4. 反向复核：**上浮与下沉**（每轮复盘必查）

经验会随着认知变化而**挪层**。定期（每轮复盘 / 主线改版 / **任何拆分搬迁之后**）做三向扫描：

★ **先做一次机械扫描，再做人工判读**（别全靠记忆）：

```bash
python scripts/audit-experience-loss.py \
  --archive "<重构前的快照目录>" --current "<skills 目录>" --only "<主题>-*"
```

它抽可辨识事实逐条查还在不在。**"找不到" ≠ "丢了"**，逐条落进：
**A 刻意丢弃**（代码内部符号 / 被新口径取代的旧值）/ **B 写法差异**（同义不同写法）/
**C 真缺口**（语义确实无处安放 ⇒ **必须补**，并按 §1 三问判断补进哪一层）。
⛔ **不做这一步 = 允许改丢东西** —— 搬迁时丢的条目不报错、不告警，只在下一次踩坑时才发现。
原因见 §0「沉底」：**经验丢了不会报错，只会让你重新踩一遍**。

### 4.1 上浮扫描（差异层 → 主线）

在**每一条**差异层里找这类句子：

- 「其实所有渠道都……」→ ⛔ **放错层了**，上浮到主线
- 同一条经验在 **≥2 条**差异层里各写了一遍 → ⛔ **重复即共性**，上浮到主线
- 「这跟渠道无关」→ ⛔ 立刻上浮

★ **重复是共性最强的信号**：同一句话在两条渠道里出现，它就**已经**是域级经验了。

### 4.2 下沉扫描（主线 → 差异层）

在主线的域级坑节里找：

- 带**模型名 / 端点 / 具体数值上限 / 计费 / 报错字符串**的句子 → ⛔ 下沉到对应差异层
- 「在 A 渠道下……」这种限定句 → ⛔ 它从来就不是主线内容

★ 用 `multi-platform-routing.md` §2 的清单做对照；校验器 4.12 会拦明显的（`N 张` / `按秒` / `¥N`）。

### 4.3 出域扫描（差异层 / 主线 → 方法论）

出现下列特征 → 抽到 `workflow-skill-builder`：

- 句子里的**专有名词全部换成占位符后仍然成立**
  （「云鲸恒 30s」→ 换成「渠道 X 恒 N 秒」就变成通用结论 ⇒ 那是方法论，不是渠道经验）
- 它是**关于"怎么管 skill / 怎么管引用 / 怎么管版本"的**，而不是关于业务本身的

> ★ 反向也成立：**方法论层里出现具体平台名或项目名 = 下沉不够**。

---

## 5. 跨域方法论沉淀（举例：本仓库已经抽出来的三条）

它们都是从具体项目里**萃取上来**的，可作为"什么叫萃取到位"的样例：

| 萃取出的方法论 | 从哪来 | 换成占位符后 |
|---|---|---|
| **引用关系必须可对账，否则静默失效** | 项目侧"规格文件会过时 → 按源重建" | 「引用方必须声明锚定的版本；改版 = 逐条对账」 |
| **参数只能整档给，不能给连续值** | 上游把未标定参数当档位吸附 | 「未标定（uncalibrated）参数一律整档给，别插值」 |
| **失败签名不是判据，提交次数才是** | 同一组反复失败，换提示词没用 | 「失败态若与'重试次数'相关，则重试是正解，改输入是错解」 |

★ 共同特征：**把具体的平台名、模型名、项目名全部剥掉之后，结论仍然有用。**
剥掉就没意义了 ⇒ 它本来就该待在原层。

## 6. 落地清单（写完一轮后逐条过）

- [ ] 每条经验都做过 **三问萃取**（换渠道 → 换项目 → 换域）
- [ ] 差异层里**没有**"所有渠道都……"这类句子（§4.1）
- [ ] 同一条经验**没有**在 ≥2 条差异层里重复（重复即共性，应上浮）
- [ ] 主线里**没有**模型名 / 端点 / 上限数值 / 计费 / 报错字符串（§4.2）
- [ ] 方法论层里**没有**具体平台名、项目名（§4.3）
- [ ] 环境事实进了**环境红线表**，没有硬塞进流程或渠道层（§2）
- [ ] 每条经验都标了**出处强度**（`实测` / `初步` / `待证`）
- [ ] 单次 / 单项目的经验**没有**被写成永久规则（走备案计数）
- [ ] ★ **做过拆分 / 搬迁 / 瘦身 ⇒ 跑过 `scripts/audit-experience-loss.py`**，
      且每条"找不到"都判读过（A 刻意丢弃 / B 写法差异 / **C 真缺口已补**）（§4）
