# 文件架构与知识治理 VNext

> 本文件是「**产出的 Skill 里，文件怎么放、怎么长、怎么死**」的唯一权威。
> 主方法见 `SKILL.md` 的「文件架构与知识治理」节；契约见 `references/vnext-contracts.md` 第 11 节。
> 职责边界：本文件只管**文件**（位置与生命周期）。能力设计、Runtime、判断路由归
> `personal-studio-standard.md`；**文件里的代码怎么写**归 `code-engineering.md`；跨平台边界归
> `multi-platform-routing.md`。

## 0. 为什么必须治理

Skill 有三个**必然**膨胀的来源：**踩坑经验、日志、测试代码**。
不管的后果不是"乱"，而是——**AI 每次都读一遍，token 用来读废话，关键规则被淹掉**。

只有一条总原则：

> **能被「按需读」的东西，永远不要放进「每次必读」的地方。**

所以任何文件进 Skill 之前，先回答一个问题：**它属于哪一层？**

---

## 1. 生命周期四层（核心思维）

| 层 | 名称 | AI 读取策略 | 典型内容 |
|---|---|---|---|
| **H** | Hot 常驻 | 每次任务开头必读 | `SKILL.md`；`README.md` 的速览段 |
| **W** | Warm 按需 | 触发条件满足才读（`SKILL.md` 写明触发） | `references/`、`templates/`、`config/`、`ARCHITECTURE.md` |
| **C** | Cold 冷存 | **默认不读**；只有索引命中当前现象时，才读索引指向的那一份 | `pitfalls/*.md` 正文、`logs/`、历史 `evidence/` |
| **D** | Dead 死稿 | **禁止读取**；保留只为追溯，并写明清理条件 | 废案、旧方案、失败实验 |

落地四条硬规则：

1. **冷存层必须有索引。** AI 只读索引，命中后才按路径读正文；**没有索引的冷存层等于不可用**。
2. **冷存层与死稿层的目录必须自我声明。** 目录内放 `README.md`，**第一段第一句**就是 `⚠ 默认不读：<什么情况下才读>`。
3. **命名要能一眼认出**：冷存用语义名（`pitfalls/`、`logs/`），死稿一律带 `_` 前缀（`_废案_xxx/`、`_旧版/`）。
4. **`SKILL.md` 的 `Load First` 只允许引用 H/W 层。** 引用 C/D 层路径 = 结构错误（`scripts/validate-skill.py` 会查）。

## 2. 标准目录骨架

```text
skill-name/
├── SKILL.md              # H｜触发 + 主流程 + Gate + 输出 + 通用避坑（唯一必读）
├── README.md             # H｜人看的定位与上手；AI 也读它的速览段
├── ARCHITECTURE.md       # W｜文件地图 + 排障定位表 + 改动影响面
├── references/           # W｜稳定方法、字段、评价规则（一个主题一份）
├── scripts/              # W｜转正后的确定性能力（名字里不带 test）
├── config/               # W｜项目差异与参数模板
├── templates/            # W｜产出物骨架（README / ARCHITECTURE / 索引等）
├── assets/               # W｜可复用资源（字体、示例图、样例数据）
├── tests/                # C｜仍在跑的回归测试（§4）
├── pitfalls/             # C｜踩坑治理（§3）：INDEX.md 是唯一默认可读项
├── logs/                 # C｜跨任务复用的运行日志（§5）
└── _归档/ 或 _旧版/       # D｜死稿层：禁止读取
```

按需创建，**禁止为结构完整建空目录**。最小可用 Skill 只有 `SKILL.md`（裁量规则见 §6）。

## 3. 踩坑治理：三级递进（**本规范最重要的一节**）

### 3.1 问题

坑越记越多 → 文件膨胀 → AI 每次通读 → token 白烧、关键规则被淹。
反过来，为了"省事"什么都不记，同一个坑会反复踩。

### 3.2 解法：**索引与正文分离 + 命中计数 + 晋升阈值**

```text
pitfalls/
├── INDEX.md            # 唯一默认可读：一行一坑
├── P001-<slug>.md      # 冷存：完整复盘 + 解决方案，默认不读
└── P002-<slug>.md
```

`INDEX.md` 列格式固定，**不要改列**（否则失去可机械解析性）：

```markdown
| ID | 一句话现象 | 命中 | 处置 | 详情 | 通用化 |
|---|---|---|---|---|---|
| P001 | 某渠道报"账号受限"其实是模型名写错 | 3 | 已晋升 | SKILL.md §避坑 | ✅ 一类操作 |
| P002 | 大目录移出父目录被宿主守卫拦 | 1 | 备案 | P002-host-guard.md | ❌ 本机专属 |
```

- **命中**：**同一个坑再次出现就 +1**。这是全流程唯一的量化依据，凭它决定处置。
- **处置**只有三种：

| 命中 | 处置 | 动作 |
|---|---|---|
| 1–2 次 | **备案** | 正文写进 `pitfalls/PNNN-<slug>.md`（现象 / 根因 / 解决方案 / 复现条件 / 已排除项）；`INDEX.md` 只留一行摘要。AI **默认不读正文** |
| ≥3 次 | **晋升** | 萃取为通用规则写进 `SKILL.md`；`INDEX.md` 标 `已晋升`，正文可留在冷存或移入死稿层 |
| 任意次数但**不可通用** | **降级** | **移出 Skill**，写进**项目自己的文档**；Skill 里不留 |

### 3.3 AI 何时才去读冷存正文

只在这三条**同时**成立时：

1. 当前现象在 `INDEX.md` 里**匹配到某一行**；
2. 该行处置是 `备案`；
3. 读的是**这一行指向的那一份 md**，而不是整个 `pitfalls/`。

⚠ 出现以下任一情况，说明索引设计失败，必须重构索引：AI 需要通读 `pitfalls/`；AI 明明匹配到却仍在猜。

### 3.4 晋升判定：**三条同时满足，缺一不可**

1. **频次**：命中 ≥3 次；
2. **通用性**：讲的必须是「**一类操作**」，不是「某项目 / 某次的具体值」；
3. **可执行**：写进 `SKILL.md` 后能**改变执行动作**，不是"注意一下"。

通用性对拍（照这个判）：

| ❌ 不可晋升（项目 / 单次专属） | ✅ 可晋升（通用） |
|---|---|
| 肥皂1 的提示词里引号得转义 | 中文内容写进 JSON 前必须转义并做 round-trip 校验 |
| 猴头菇1 要同时开 2 个实例 | 云实例按小时计费，跑完必须关，空转照扣 |
| 这次 H3 的 710 号段被占了 | 节点号必须独享号段，撞号只报无意义的依赖环 |
| 这台机器删目录会被守卫静默改语义 | ——（机器专属，写进环境文档，不进 Skill） |

### 3.5 反污染红线（**违反即算 Skill 缺陷**）

- **单项目 / 单次操作的经验，绝不允许直接写进 `SKILL.md`。**
- 晋升前必做一次「**换个项目还成立吗**」自检；答不上来就不晋升。
- `SKILL.md` 避坑节**只收通用条目**，每条一行，写「现象 → 动作」，**不写案例故事**。
- 每晋升 1 条，同时检查有没有**能删掉**的旧条目 —— 只增不减的 Skill 会烂。

## 4. 测试代码治理：**毕业制**

### 4.1 位置

```text
tests/       # 开发期所有测试 / 试验 / 探针代码的唯一去处
scripts/     # 转正后的生产代码（名字里不带 test）
```

**`scripts/` 下永远不该出现 `test_*` / `*_test.*`。** 出现就是没毕业，校验脚本会报错。

### 4.2 三种处置

| 试验代码的结局 | 动作 |
|---|---|
| **有用，长期要跑** → **转正** | 移到 `scripts/`；**文件名去掉 `test_` / `_test` / `try_` / `tmp_` / `skill` 等草稿标记**，改成语义化能力名（`test_parse_groups.py` → `parse_groups.py`）；在 `ARCHITECTURE.md` 的能力表登记一行 |
| **还有用，但只是回归样本** → **留在 `tests/`** | 必须**真的还在跑**。超过 30 天没跑过 = 死稿 |
| **废掉 / 失败 / 已过时** → **直接删除** | 不进 `tests/`、不进 `SKILL.md`、不进冷存。有 git 就是天然历史；没有 git 时先 `_归档/` 兜一次再删 |

### 4.3 一句话判据

> **`scripts/` 里的文件必须「产品要它」；`tests/` 里的文件必须「我还在跑它」。两个都不满足 → 删。**

不留"以后可能有用"—— 那是最贵的四个字。

## 5. 日志与运行数据治理

### 5.1 默认归属：**任务目录，不是 Skill 目录**

一次任务的日志、state、checkpoint、评审、trace、预览、交付物，**全部进任务文件夹**。
Skill 目录**只允许**放「跨任务复用的运行日志」—— 不看它就没法排障的那种。

### 5.2 允许有 `logs/` 时的四条硬规则

1. 目录内必须有 `logs/README.md`，写清**保留策略**（多少天 / 多少条 / 谁清理）；这是本目录**唯一**可被 AI 默认读的文件。
2. **日志不做 AI 的默认输入。** 排障时只读**尾部 N 行**（建议 ≤100 行），禁止整读。
3. **轮转**：超保留量 → 移入 `logs/archive/`（死稿层）或直接删（有 git 就不需要 archive）。
4. **原始日志与总结分开。** 原始日志 = 冷存；"给 AI 看的结论" = `references/` 或 `SKILL.md`。**禁止混在一个文件里。**

### 5.3 大文件红线

单个日志 / JSONL / 转写文件 > 5 MB → 不进 Skill 目录，也不进任务目录的常读路径；
放项目外的数据目录，任务目录里只留 **路径 + 摘要**。

## 6. Skill 文档三件套

| 文件 | 读者 | 写什么 | 何时可以省 |
|---|---|---|---|
| `SKILL.md` | **AI（执行）** | 触发、主流程、Gate、输出、通用避坑 | **永不可省** |
| `README.md` | **人 + AI 速览** | 一句话定位、适用 / 不适用、30 秒上手、目录导航、依赖 | 整个 Skill ≤1 个文件且 `SKILL.md` ≤2400 字符 |
| `ARCHITECTURE.md` | **后续 AI（排障 / 改造）** | 文件地图、现象 → 查哪里、改动影响面、校验与重建命令 | 已存在 `scripts/` 或 ≥2 份 `references/` 时 **必须有** |

`ARCHITECTURE.md` 是"后续 AI 的排障地图"，最小四段（模板见 `templates/ARCHITECTURE.template.md`）：

```markdown
## 1. 文件地图        # 每份文件：谁是权威、谁可改、谁默认不读
## 2. 现象 → 查哪里    # 表格：现象 | 先看 | 常见根因
## 3. 改动影响面      # 改 X 必须同步改 Y（漏改就是这里没写）
## 4. 校验与重建      # 一条命令跑通自检 / 从零重建
```

> 有人担心 README / ARCHITECTURE 会给 AI 添 token —— 不会。
> README 只在人需要或 AI 初识 Skill 时读一次；ARCHITECTURE **只在排障时读**。
> 真正杀 token 的，是把它们的内容**塞进 `SKILL.md`**。

### 6.1 重大决策要留一句「为什么」

**影响面大或不可逆**的技术选择（换渠道、换数据结构、改输出契约、放弃某个方案），
在**项目侧**留一条短记录：背景 / 考虑过的选项 / 决定了什么 / 代价是什么 / 什么条件下可推翻。
放项目的 `docs/decisions/`（或 `_决策/`），**一条 10 行以内，不进 Skill 目录**。

判据：**半年后有人问「当初为什么不用另一种方案」，能一条链接答上来。**
只对上面那类决策写 —— 每个小改动都写等于没写。

## 7. 目录什么时候该重构（触发信号）

结构不是一次设计完的。出现以下**任一**信号就重排：

| 信号 | 阈值 | 动作 |
|---|---|---|
| `SKILL.md` 与内容规模不匹配 | 见下方「规模口径」（**文档不按字数判**） | 抽出 `references/`；`SKILL.md` 只留触发 + 主干 + Gate + 硬规则 |
| 代码单文件过大 | **代码** > 300 行（硬线 600） | 拆模块。★ 代码按**行数** —— 见下方「规模口径」。细则见 `code-engineering.md` §0 第 7 条 |
| 索引膨胀 | `pitfalls/INDEX.md` > 40 行 | 已晋升项归档，只留未晋升 |
| 测试死化 | `tests/` 中 > 30% 超 1 个月没跑 | 清理，只留活的 |
| 同一个坑在 ≥3 个项目各记一遍 | — | 早该晋升 → 去重 + 通用化 + 写 `SKILL.md` |
| 出现「每次都读、每次都用不上」的段落 | — | 下沉到冷存层，或删 |
| 单目录平铺 > 15 个文件 | — | 加一层语义分组 |
| 出现 `.bak` / `_v2` / `_final` / `副本` | 任意一个 | 用 git 取代，立即清理 |

### 规模口径：**只有代码按行数，文档字数不设门槛**

★ **2026-10-02 起，文档字数门槛全部废除。** 历史上这里有整套数字
（`SKILL.md` 8000 参考线 / 12000 硬线；`references/` 单份 12000 软线 / 20000 硬线；
人读文档 20000 提示线）—— 它们**一律不再判定、不再提示**。
理由：这些数字是**本规范自设、非平台限制**；**域级 skill（提示词规范层、渠道协议、
母工作流）天然超出**，一刀切只会逼人把内容切碎成难以使用的碎片。
校验器不该替作者做这个取舍 —— **判断权交回作者**。

| 对象 | 判据 | 说明 |
|---|---|---|
| **文档**（`SKILL.md` / `references/` / README / ARCHITECTURE） | **不判、不提示** | 字符数与行数只进报告 **INFO 行**，是**信息**不是门槛，永不参与 PASS/FAIL |
| **代码**（`scripts/`） | **行数 > 300** WARN，**> 600** ERROR | 代码吃的是「复杂度 / 职责量」。`}`、缩进、短标识符让字符密度很低 —— 600 行代码可能只有 12000 字符，字符数**反而不反映规模** |

> **为什么文档连「字符数」也不判**：读一次要花多少上下文，作者比校验器更清楚。
> 需要下沉时（§1 四层）作者自己会下沉；不需要时，硬砍只会制造难用的碎片。
>
> **为什么代码仍按「行数」**：代码的规模 = 职责量，而字符密度失真（见上表）。
> 唯一一条规模硬门槛就落在这里。

> ⚠ 顺带说明：WorkBuddy 内置 `skill-creator` 对 `SKILL.md` body 的建议是
> `<5k words`，但它**不做强制** —— 它自带的 `cloud-service` 就有 32K 字符
> ≈ 6355 英文词，已超它自己那句建议。**本规范同样不强制。**
>
> 废除门槛**不等于**取消分层原则（§1）：`SKILL.md` 仍应只放
> **触发 + 主干 + Gate + 硬规则**，细节仍该下沉 `references/`。
> 区别只是：**判断权交回给你**，而不是由字符数一票否决。

### 7.1 `references/` 的拆分

`references/` 的拆分不看字数，只看**主题**：

| 规则 | 说明 |
|---|---|
| **一个主题一份文件** | 同主题就该在一份里读完；跨主题混装才拆 |
| 命中时整份被读进来 | 所以「一份 = 一个可独立命中的主题」是拆分依据 |
| 禁止收容所 | 不设 `misc.md` / `notes.md` / `other.md`（§8） |
| 人读文档（README / ARCHITECTURE / pitfalls） | 压根不在每次读取路径上，**只按有无目录 / 索引**要求，不按规模 |

> 真正该管的是**进了 `SKILL.md` 的内容**（每次触发都付成本）——
> 但它同样**不由字数来判**，而由「这内容是不是每次都用得上」来判（§1 四层）。

## 8. 命名与版本

- **版本交给 git。** 禁止在 Skill 里留 `.bak` / `_v2` / `_final` / `(1)` / `副本` 后缀。
- 没有 git 时：`_归档/<名称>_<YYYYMMDD>/` 一次性兜底，**兜完就删**。
- **文件名禁止残留草稿标记**：`test_` / `_test` / `tmp_` / `try_` / `new_` / `old_` / `skill`。
- 目录名用**语义名**；`_` 前缀 = 默认不读（死稿层）。
- 一个主题一份文件。**禁止 `misc.md` / `notes.md` / `other.md` 这类收容所。**

## 9. 产出 Skill 的落地清单（写完逐条过）

- [ ] 每个目录都能回答「属于 H / W / C / D 哪一层」
- [ ] 冷存层与死稿层的目录内都有自声明 README（`⚠ 默认不读`）
- [ ] `SKILL.md` 的 `Load First` **没有**引用冷存层 / 死稿层
- [ ] 有 `pitfalls/` 就有 `pitfalls/INDEX.md`，且列格式未被改
- [ ] `scripts/` 下没有 `test_*` / `*_test.*` 残留
- [ ] 没有 `.bak` / `.DS_Store` / `__pycache__` / `node_modules` / 运行产物目录
- [ ] `SKILL.md` > 2400 字符 → 有 `README.md`；有 `scripts/` 或 ≥2 份 `references/` → 有 `ARCHITECTURE.md`
- [ ] **文档字数不设门槛**：`SKILL.md` / `references/` / README / ARCHITECTURE 再长也不判、不提示（§7 规模口径）
- [ ] `references/` 按**主题**拆（一份一个可独立命中的主题），不按字数拆（§7.1）
- [ ] **多平台 / 多版本**任务已拆成「一条主线 + N 个渠道差异层」：主线有全流程、差异层只写差异、锚点已声明
      （见 `multi-platform-routing.md` §8）
- [ ] `scripts/` 单文件 ≤ 300 行（例外已在 `ARCHITECTURE.md` 逐文件声明）
- [ ] 业务代码里没有密钥 / 令牌字面量（改走环境变量或独立配置文件）
- [ ] 跑过 `python3 scripts/validate-skill.py <skill-dir>` 且 PASS
