# 多平台 / 多版本：主线与渠道差异层 VNext

> 本文件是「**同一件事有多个平台能干时，skill 怎么拆、怎么调度**」的唯一权威。
> 主方法见 `SKILL.md` 的「多平台与多版本」节；契约见 `references/vnext-contracts.md` 第 12 节。
> 与 `file-governance.md` 的分工：那边管**一个 skill 内部**的文件，这边管**多个 skill 之间**的边界。
>
> ★ 术语变更：「中控 / router」**已废弃** —— 它暗示"只做路由"，正是 §1.1 要修的病。
> 新术语：**主线（mainline）** ＋ **渠道差异层（channel overlay）**。

## 0. 问题

同一件事往往有多个平台能干，且**约束完全不同**：

| 差异面 | 例子 |
|---|---|
| 参数上限 | 参考图上限 9 张 vs 10 张 |
| 时长口径 | 恒 30 秒 vs 整数 4–15 秒 |
| 输入能力 | 能不能传参考音频（一条不能传） |
| 计费模型 | 按次 / 按秒 / 按小时 |
| 调用协议 | 字段名不同（`reference_images` vs 把引用写进 prompt） |
| 资源生命周期 | 参考图 URL 只活 1 小时、且不去重 |
| 流程步骤 | 一条要"先传图床再提交"，另一条可直接复用 |
| 失败模式 | 上游把假报错伪装成正式错误码 |

**两种错误拆法，都要避免**：

| | 错误拆法 | 症状 | 后果 |
|---|---|---|---|
| ❌ A | 全塞进**一个** skill | `SKILL.md` 里长出 if/else 分支 | AI 每次要读**全部平台**约束（烧 token、关键规则被淹）；★ **参数串味** —— 把 A 平台经验套到 B 平台，报错还查不出来 |
| ❌ B | 拆成「**每个渠道一份完整流程**」 | N 条渠道各自把全流程重写一遍 | ★ **流程漂移** —— 改一处要改 N 份；A 补了半句 B 忘了补 → 同一流程出现两种说法；**加新渠道 = 抄一遍全流程** |

⇒ **正确解：全流程只有一个权威（主线），渠道只写差异。**

---

## 1. 正确结构：一条主线 + N 个渠道差异层

```text
skills/
├── <domain>-creation          # ★ 主线：全流程（阶段 / 产出物 / 闸门）+ 分叉点声明
├── <domain>-<channel-a>       # 渠道差异层：只写"本渠道相对主线不同在哪"
├── <domain>-<channel-b>       # 渠道差异层
└── <domain>-<channel-c>       # 渠道差异层
```

**边界一句话**：**与渠道无关的流程骨架归主线；因渠道而异的一切归差异层。**

差异层是**独立 skill，不嵌进主线目录** —— 只有被路由到的那一条会进上下文，其余**一个字都不读**。

### 1.1 主线必须完整（不许退化成"只做路由"）

★ **主线 = 这个域最初的那个 skill**。它本来就该有全流程；引入多渠道**不得把它掏空**。

**出现下列任一 = 主线被掏空了（结构错误）**：

- 主线里**只有**路由表，找不到全流程的阶段；
- 主线把某个阶段写成"见 `<某渠道>` skill"（把共性推给了渠道）；
- 读者看完主线，**不知道这件事整体上要做哪几步、每步什么条件下才做**。

---

#### 1.1.1 主线的粒度下限：**每个阶段必须给足五要素**

★ 光有「阶段名 + 一句产出物」**不够** —— 那叫目录，不叫流程。
每个阶段（含被拆出去的阶段文件）**必须**给足下面五条，**缺一即视为"颗粒度不足"**：

| # | 要素 | 写什么 | ❌ 不够原子的写法 |
|---|---|---|---|
| ① | **进入 / 跳过条件** | 这一步**什么情况下不用做**、什么情况下必须做；依赖上一步的哪个产物 | 「Phase 1 剧本处理」——没说剧本**已带时长**就跳过 |
| ② | **看什么文件** | 这一步的**输入**与**权威规范文件**（给**路径**，不给"按规范"这种空话） | 「按规范写提示词」——没说是哪一份 |
| ③ | **做什么** | 动作序列；★ **有条件分支就把分支写出来**（if A → 走 X；否则 → 走 Y） | 「分批盘点 + 合并去重」——太笼统，看不出何时走哪条 |
| ④ | **产出什么** | 落盘路径 + 命名规则（含"不产出什么"这种负向约束） | 「产出资产图」——没路径、没命名 |
| ⑤ | **闸门** | CP / 门禁 + **谁批** + 没过怎么办 | 只字不提 |

> **为什么必须有 ①**：流程里真正会出错的地方，**几乎都在"这步该不该做"上**。
> 只写"做什么"、不写"什么时候不做"，读者就会**对着已经做完的步骤再跑一遍**
> （重跑 = 白烧钱 / 覆盖已完成产物 / 全量重编号作废已交付物）。
>
> **为什么必须有 ②**：规范文件往往不止一份（每个资产类型一份、每个渠道一套）。
> 不写路径，执行者只能靠猜 —— 而**猜错规范文件是最高频的返工原因**。

★ **阶段多或步骤长时，一个阶段一份文件**（`<phase>-<名>.md`），
主文件只留**总览表 + 分叉声明 + 加载指引**，让执行者**走到哪一步只读那一份**。
判断依据：**「阶段内部有分支判断 / 有多份输入文件 / 步骤数 ≥3」⇒ 就该独立成文件。**

---

#### 1.1.2 骨架 vs 实现：正确的切分线是**「换渠道还成立吗」**

❌ **旧判据（错，且已造成过一次真实事故）**：
> 「主线只写阶段名 / 产出物 / 闸门；**不写具体命令、端点、参数、模型名、计费**」

它只说了**不写什么**，没说**写到多细才算够** —— 于是被读成「一句话 + 一张表」就够了，
主线被掏成目录，`manju-creation` 的 Phase 1/2/3 一度只剩"跑一条命令"这一句话。

✅ **新判据**：对每一条信息问一句 ——

> ## ★「**这条信息 / 这个取值，换个渠道还成立吗？**」

| 问的结果 | 归属 | 举例 |
|---|---|---|
| **成立**（换渠道不变） | ★ **主线** —— **哪怕它是具体路径、具体判据、具体命令骨架** | 权威规范文件的**路径**；「剧本已带时长就跳过」的判据；编排命令的骨架；产出目录与命名规则；CP 门的判据 |
| **不成立**（取值因渠道而异） | **渠道差异层** | 模型标识、端点、字段名、上限数值、计费口径、报错特征、该渠道的坑 |

⇒ 所以「**是不是命令**」**不是**判据，「**这条取值会不会因渠道而异**」**才是**。

主线**可以也应当**写：文件路径、判据阈值、命令骨架、产出路径、门禁判据。
主线**不许**写：**取值因渠道而异的**东西（见 §2）。

---

#### 1.1.3 每个分叉阶段要放显式声明

```markdown
### Phase 4｜出片提交
产出物：<...>　闸门：<...>
> ⚠ 本阶段因渠道而异 → 读当前渠道差异层的「Phase 4」。差异层未覆盖的，按本节执行。
```

★ **主线不写渠道细节，但必须写清"差异层该补什么"** ——
列一张「差异层需要覆盖的点」清单（资源准备 / 自检门 / 提交策略 / 失败处置 / 计费闸），
否则差异层会漏写，而漏写**不会报错、只会静默跑错**。

---

#### 1.1.4 经验也要分层萃取（不许沉底）

★ 一个域的"经验"不是一坨。**写进去之前必须先萃取**，判据同样是
**「换个渠道还成立吗」** —— 完整三层见 `experience-distillation.md`。

一句话版：

| 经验的适用范围 | 归属 |
|---|---|
| 跨渠道成立 | **主线**（域级坑节）或域级通用 skill |
| 只对本渠道成立 | **该渠道差异层**（`Own Pitfalls`） |
| 不随渠道、不随项目变，但也不是流程 | **环境红线**（项目 `MEMORY.md`）/ `docs/经验与避坑.md` |
| 跨域成立 | `workflow-skill-builder`（方法论） |

⛔ **差异层里"换渠道仍成立"的经验 = 放错层了**，必须上浮到主线。
每轮复盘都要查这一条（见 `experience-distillation.md` §4）。

### 1.2 差异层只写差异（不许复述主线）

差异层里**只允许**出现"相对主线不同"的内容。

★ **自检判据**：**把差异层里所有与主线重复的段落删掉，剩下的才是它该有的内容。**
删完几乎没剩什么 → 它被写成了主线的副本，**结构错误**。

每种差异必须标类型：

| 类型 | 含义 | 例子 |
|---|---|---|
| `replace` 替换 | 主线那一步**整套换掉** | 本渠道的提示词规范与主线完全不同 |
| `append` 追加 | 主线之外**多做的步骤** | 提交前必须先预热图床 / 必须先开云端实例 / 多跑一道门 |
| `forbid` 禁止 | 主线的某做法**在本渠道不成立** | 本渠道不接受参考音频；不许开某开关 |

差异层按**主线的阶段名**组织，一节对一阶段；**没差异的阶段不写**
（不要写"本阶段与主线相同"这种占位）。

---

## 2. 哪些东西必须留在差异层（防串味，这条不放松）

★ 拆分的第一目的仍然是**防参数串味**。下列内容**只能**出现在差异层，
**主线（含路由表）里一律不许写**：

| 只能进差异层的 | 说 明 |
|---|---|
| 模型标识 | 逐字符照抄；写错时上游常伪装成别的错误 |
| 端点 / 鉴权 | 调用协议差异 |
| 参数上限 | 参考图张数、时长、画幅、必填字段 |
| 计费 | 按次 / 按秒 / 按时、单价、预估成本闸 |
| 失败信号 | 哪条是真失败、哪条是假报错、哪条可捞回、哪条只能重跑 |
| 本渠道的坑 | 跨渠道共性问题归主线或域级 skill |

出现下列任一 = **结构错误**：

- 主线 `SKILL.md`（或路由表）里出现渠道专属数值（`9 张` / `按秒` / `每小时 ¥3`）；
- 主线里写了某渠道的报错特征或坑；
- 主线的 `Load First` 列了**各渠道差异层 skill**（应该只列**路由表**）。

### 路由表格式（固定列，勿改）

```markdown
| 渠道 | 触发词 | 差异层 skill | 关键差异（一句话） | 协议文档 |
|---|---|---|---|---|
| A | 点名 A / 模型名拼写 | `<domain>-channel-a` | 按次计费、时长固定、不能传音频 | `<path>` |
```

- 「关键差异」列的作用是**帮 AI 选**，不是**替 AI 执行** —— 写**能力形态**，不写数值。
- 「差异层 skill」列必须是**真实存在的同级 skill 名**（死路由会被校验脚本判错）。

## 3. 渠道差异层 skill 的硬规则

- ★ **只写差异**：按 §1.2 的组织方式，一节对主线一个阶段；没差异的阶段不写。
- ★ **禁止复述主线**：不得把主线的阶段描述、闸门、交付规范抄一遍。
- ★ **禁止跨渠道引用**：不得写「和 B 渠道一样，只是……」。
  理由：B 渠道改了，这条路引用**不会知道**，会静默失效。
  （★ 注意区分：**引用主线是允许且必须的**；**引用另一条渠道是禁止的**。）
- ★ **锚点声明**（见 §4）：头部必须写清锚定的是哪一版主线。
- `description` 必须覆盖用户**实际会说的**触发词：正式名、口语简称、旧名、平台名、模型名的各种拼写。
- `references/` 里必须有**本渠道协议文档**：模型标识、端点、鉴权、字段、计费、上限、失败信号。
- 坑**只记本渠道的**；跨渠道的共性问题属于主线或域级通用 skill。

---

## 4. 锚点与对账（替代旧「禁止一切引用」的防线）

差异层引用主线，等于**依赖主线的某一版措辞**。主线改了，差异层**不会自动知道** ——
这正是旧规范禁止"和 B 一样"的原因。新模型下引用是必要的，所以**必须补一道显式防线**：

1. ★ **差异层头部声明锚点**：`锚定主线版本：<主线里的 Version 或日期标记>`
2. ★ **主线带版本标记**：主线 `SKILL.md` 里必须有可见的版本 / 日期（改版时递增）。
3. ★ **主线改版 = 对账所有差异层**：改完主线，**逐个**差异层核对它的分叉节是否仍成立；
   对账结果记进主线或项目台账。**没有对账的主线改版视为未完成。**
4. **对账要机械可查**：差异层声明的锚点版本 ≠ 主线当前版本 → 就是"待对账"清单。

> 这和项目侧「规格文件会过时 → 必须按源重建」是同一个道理：
> **引用关系必须可对账，否则静默失效。**

## 5. 拆分判据：满足任一就拆

| 判据 | 说明 |
|---|---|
| 模型名不同 | 模型标识不同 = 不同的东西 |
| 参数约束不同 | 上限、时长、画幅、必填字段 |
| 计费模型不同 | 按次 / 按秒 / 按时 |
| 调用协议不同 | 端点、字段名、鉴权方式 |
| 流程步骤不同 | 多一步或少一步（先传图床、能不能带音频） |
| 资源生命周期不同 | URL TTL、是否去重 |
| 失败模式不同 | 失败信号的形态与处置 |

**反判据（不该拆）**：

- 只是同一协议下的**参数取值不同**（换分辨率、换画幅、换语气档）→ 那是 `config/`，不是新 skill。
- ★ **只是流程骨架一样**（"要做的事"相同）→ 那**不是**拆分理由，骨架本来就该在主线里共用。
  拆分只由**上面七条差异**触发，**不由"渠道数量"触发**。

## 6. 多版本：同平台多版本 = 多个差异层 skill

**硬规则：同一平台的不同版本各建一个差异层 skill，不用 if/else 分支。**

- 命名：`<domain>-<platform><major>`（例：`...-jimeng20` / `...-jimeng25`）
- 弃用版本：`description` 标 `[已弃用/历史]`，路由表标 `历史`；主线**默认不选**，除非用户点名。
- ★ **未来加版本 = 加一个差异层 skill + 路由表加一行，不动任何存量 skill**。
  ← 这是拆分最大的收益：新平台不会逼你回去改老 skill，也不会逼你抄一遍全流程。

## 7. 代码侧：API 三件套（Skill 拆了，代码必须跟着拆）

否则参数照样串味。

```text
registry（数据）   → 每个平台/版本一行：模型名、端点、鉴权、计费、上限、能力开关、失败信号
client（实现）     → 每个平台一个 client，只认自己那套字段
scheduler（决策）  → 选路 + 限流 + 重试 + 计费闸
```

硬规则：

1. ★ **业务代码里禁止出现模型名字符串。** 模型名只允许出现在 registry。换模型 = 改 registry 一行。
2. **能力查询必须走 registry**，不要在业务里写 `if 平台 == X`。
3. **选路顺序固定**：`能力是否满足 → 成本 → 可用性`。能力不满足直接淘汰，**不参与比价**。
4. **计费闸**：提交前先算预估成本并过闸；没有成本估算的批量提交视为缺陷。
5. ★ **协议文档按渠道分割**：`<渠道>/<协议>.md`。
   **禁止一份文档写多个平台** —— 一份文档混装是参数串味的头号来源。
6. **失败信号也进 registry**（哪条是"假失败"、哪条可捞回、哪条只能重跑）。

## 8. 调度纪律

- **一次任务只跑一条渠道线**，禁止并行两条 —— 参数会串味。
- 用户点名 → 直连该渠道；**未点名 → 走默认渠道，并在回复里显式声明用了哪条**。
- ★ **主流程从主线走一遍，不因换渠道而重写**；换渠道 = **只换差异层的取值**，
  **不重跑与渠道无关的阶段**（除非该阶段在差异层里标了 `replace`）。
- 跨渠道比价 → 只读各渠道的**能力 + 计费摘要**，不读全文。
- 云端资源（实例 / 图床 URL）**按渠道分别记账**，别跨渠道复用生命周期。

## 9. 拆分落地清单

- [ ] 主线 `SKILL.md` **有完整全流程**（阶段 / 判据 / 产出物 / 闸门），不是只有路由表
- [ ] ★ **每个阶段给足五要素**（进入·跳过条件 / 输入与**规范路径** / 做什么含**分支** / 产出含**负向约束** / 闸门含**谁批**）
- [ ] ★ **有分支判断 / 多份输入文件 / 步骤 ≥3 的阶段已独立成 `references/<phase>-*.md`**，主文件只留总览与加载指引
- [ ] ★ 总览表**有「进入 / 跳过条件」列**，并给出去向（详读哪份文件）—— 不能只列阶段名
- [ ] 主线的每个分叉阶段都写了「⚠ 本阶段因渠道而异 → 读差异层」声明
- [ ] ★ 每个分叉阶段**列了「差异层该补什么」清单**（漏写不报错、只会静默跑错）
- [ ] 主线里**没有**任何渠道专属数值 / 模型名 / 计费 / 报错特征 / 坑
